# Contributing

Thanks for improving Clone Engine.

## Scope

This is a public architecture and explainer site. Keep contributions within that boundary. Do not add third-party transcripts, quotes, source captures, client records, embeddings, credentials, or claims that a system is an actual person.

## Before opening a pull request

1. Keep the language source-grounded and non-impersonating.
2. Add accessible alt text for any visual asset.
3. Keep source, client, and derived-knowledge examples synthetic or rights-cleared.
4. Run `npm run lint` and `npm test`.
5. Explain the user-facing change and any new public-data exposure in the pull request.

## Design principles

- Evidence before imitation.
- Attribution before extraction.
- Judgment before style.
- Client isolation before convenience.
- Independent audit before release.

## Pull requests

Small, focused pull requests are easiest to assess. If a change affects the release posture or provenance model, call that out explicitly and include the relevant test or documentation update.
